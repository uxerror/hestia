# 02f. Этап 1e-2 — сканирование сети, сервисы, карта

Цель: Hestia сама находит устройства и сервисы в домашней сети, связывает их с инвентарём
Proxmox (1e-1) и показывает на экранах «Карта сети» и «Сервисы». Только чтение: никаких
попыток входа, только TCP connect, баннеры и GET на фиксированный список путей.

## Решения (2026-11-18, с пользователем)

- Что сканируем: IPv4-подсети мостов узлов подключённых Proxmox-целей (`/nodes/{n}/network`,
  поле `cidr` у мостов) и подсети интерфейсов SSH-серверов (`ip -4 -j addr`), плюс подсети,
  добавленные вручную. Список исключений (по умолчанию пуст). Подсети, не входящие в мосты/интерфейсы
  (например отдельная сеть BMC/iLO за роутером), не сканируются, пока их не добавить явно. Подсеть больше /22 — отказ с пояснением. Позже, с плагином MikroTik,
  карта покажет всю сеть (DHCP leases, ARP, интерфейсы роутера) — модель данных к этому готова
  (`source` у хоста).
- Порты: ~150 типичных портов сервисов (список ниже), только TCP connect — контроллер
  работает в непривилегированном LXC без raw-сокетов и без ICMP (`ping_group_range` закрыт).
- Когда: по кнопке и автоматически раз в 6 часов (первый автозапуск — через 5 мин после старта,
  если последнего скана нет или он старше 6 ч). Одновременно — один скан.
- Где выполняется: в процессе контроллера (в LXC контроллера после самоустановки; на ПК, пока Hestia локальная).

## Обнаружение хостов

- Для каждого адреса подсети (кроме сетевого и широковещательного, кроме исключений): TCP connect
  ко всем портам списка. Таймаут соединения 700 мс; одновременно не больше 256 соединений на скан
  (лимит `nofile` службы — 1024) и 24 на хост. Порядок — перемешанный, чтобы не бить один хост подряд.
- Хост жив, если: хоть один порт открыт ИЛИ получен RST (`connection refused`) ИЛИ после прохода в
  `/proc/net/arp` есть запись с флагом `0x2` (complete) для этого IP. Таймауты — не признак жизни.
- MAC — из `/proc/net/arp` (только для подсети, в которой у контроллера есть интерфейс), из
  инвентаря Proxmox (net0 hwaddr у LXC/QEMU — дополнить сбор 1e-1, если его там нет), иначе пусто.
  Производитель — по встроенной таблице OUI IEEE (`internal/netscan/oui/oui.tsv.gz`, embed,
  `ASSIGNMENT<TAB>Organization`); MAC с битом locally administered → «случайный MAC» (телефоны,
  ноутбуки с приватным адресом).
- Имена: PTR через системный резолвер (таймаут 1 с, параллельно ≤ 16), имя гостя/узла из инвентаря,
  CN/SAN сертификата, `<title>` — в `names[]` с источником.
- На не-Linux (desktop на macOS/Windows в будущем) чтения ARP нет — просто без MAC.

## Отпечатки сервисов

На каждый открытый порт — не больше 3 с, одновременно ≤ 32 проб на скан:
- **Баннер** (ssh, ftp, smtp, telnet и любые порты без HTTP): прочитать до 256 байт за 1,5 с без
  отправки данных. SSH: `SSH-2.0-<soft>` → продукт и ОС (`OpenSSH_10.0p2 Debian-7+deb13u4` →
  OpenSSH 10.0p2, Debian 13; `ROSSSH` → MikroTik RouterOS; `mpSSH` → HPE iLO; `dropbear` → Dropbear).
- **HTTP/HTTPS**: порты 80/81/443/8006/8007/8080/… и любой порт, где первые байты ответа похожи
  на HTTP (или TLS-рукопожатие удалось). `GET /` с `User-Agent: Hestia/<версия> (network inventory)`,
  без перехода по редиректам, тело до 64 КБ. Записать: статус, `Server`, `Location`,
  `<title>`, имена cookie (без значений), для TLS — subject CN, SAN, issuer, notAfter,
  самоподписанный или нет. Если порт отвечает TLS — сначала HTTPS.
- **Доп. пути** (только при совпадении предварительного правила, не больше 2 запросов на сервис):
  AdGuard Home — `GET /control/status` (401 или 200 JSON с `dns_addresses`/`version`), Jellyfin —
  `GET /System/Info/Public`, Gitea — `GET /api/v1/version`, Home Assistant — `GET /manifest.json`.
- **Правила** — таблица в коде (`[]Rule{ID, Name, Category, Match}`; Match — функция над
  собранными фактами), порядок от специфичных к общим. Минимум:
  Proxmox VE (Server `pve-api-daemon` / title «Proxmox Virtual Environment»), Proxmox Backup Server
  (title «Proxmox Backup Server»), AdGuard Home (`/control/status`; на 80/443 за nginx — редирект на
  login.html), MikroTik RouterOS (title RouterOS / ssh ROSSSH / 8291 / 8728), Nginx Proxy Manager
  (title), Gitea (title / cookie `i_like_gitea`), Synology DSM, HPE iLO (ssh mpSSH / тело iLO),
  Zabbix, Gotify, Semaphore UI, Docmost, qui (qBittorrent UI), qBittorrent, Navidrome, Jellyfin,
  Plex, Home Assistant, Portainer, Grafana, Prometheus, Netdata, Syncthing, Webmin, Cockpit,
  MinIO/RustFS (S3 XML-ответ, 9000/9001), Homepage, Iris, Samba/SMB (139/445 открыты), NFS (2049),
  PostgreSQL (5432), MySQL/MariaDB (3306, баннер), Redis (6379), MQTT (1883), DNS (53), SOCKS (1080),
  NoMachine (4000), AirPlay (7000 rtsp), CUPS/IPP (631); общие: «Веб-сервер nginx/Apache/OpenResty»
  (default page), «HTTP», «SSH», «Открытый порт N».
- Категории: `infra` (гипервизоры, роутер, BMC), `network` (DNS, proxy, VPN), `storage`, `media`,
  `dev`, `monitoring`, `home`, `db`, `remote`, `other`.
- URL сервиса для веб-интерфейсов: `scheme://ip:port/` (без порта для 80/443); DNS-имена из PTR и
  сертификата показываются рядом (в 1f добавятся rewrite из AdGuard).

## Связь с инвентарём

IP хоста ищется в последних снимках инвентаря: узел Proxmox (IP из cluster status / bridges) →
`kind: node`; гость → `kind: guest` + target_id, vmid, node, name, тип. MAC из инвентаря
дополняет/проверяет ARP. Хост из инвентаря (гость запущен, есть IP), не ответивший при скане,
показывается с пометкой «не отвечает на порты из списка».

## Хранение

- `scans(id, started_at, finished_at, subnets JSON, stats JSON, error)` — последние 50.
- `hosts(ip TEXT PRIMARY KEY, mac, vendor, random_mac, names JSON, first_seen, last_seen,
  last_scan_id, alive INTEGER, source TEXT, ports JSON, services JSON, link JSON)` — обновляется
  каждым сканом; не найденный в последнем скане → `alive=0`, данные остаются (последнее
  известное). `source`: `scan` (позже `mikrotik`, `manual`). Кнопка «Забыть» удаляет запись.
- Настройки (`settings`): `netscan.extra_subnets`, `netscan.exclude` (по умолчанию `[]`), `netscan.interval_hours` (6).

## Задача и API (с входом)

- Задача `netscan` «Сканирование сети»: шаги «Подсети» (итоговый список и откуда), «Обнаружение»
  (прогресс: проверено N из M адресов, найдено K), «Отпечатки», «Сохранение». Лог — сводка без тел
  ответов. Отмена задачи останавливает скан (контекст).
- `GET  /api/v1/network` → `{last_scan, next_scan_at, subnets:[{cidr, source}], exclude[], hosts[]}`.
- `POST /api/v1/network/scan` → 202 `{job}` | 409.
- `PUT  /api/v1/network/settings` `{extra_subnets[], exclude[]}` — валидация CIDR, размер ≤ /22.
- `DELETE /api/v1/network/hosts/{ip}` — забыть хост.
- `GET  /api/v1/network/events` (SSE) или переиспользовать события задач — по ходу скана UI
  обновляет список.

## Интерфейс

- **«Карта сети»** (`#/map`, пункт меню вместо заглушки): `@xyflow/svelte` + раскладка `dagre`
  (сверху вниз). Узлы графа: роутер (шлюз подсети) → узлы Proxmox и прочие устройства → гости
  узлов. Устройства без связи группируются по категориям/производителю («Сеть», «Серверы»,
  «Клиенты», «Неизвестные»). Карточка узла графа: имя, IP, значки-сервисы (иконки по категории),
  цвет рамки — жив/не отвечает/остановлен. Клик → боковая панель: MAC/производитель, имена,
  открытые порты, сервисы со ссылками, связь с гостем (переход в «Системы»), first/last seen.
  Фильтр «показывать клиентов/остановленных», поиск, кнопка «Сканировать», время скана.
  Позиции не сохраняем (раскладка каждый раз).
- **«Сервисы»** (`#/services`): таблица — сервис, категория, хост (имя/IP), порт, URL (ссылка
  «Открыть»), версия/детали, DNS-имена. Группировка по категории, поиск, фильтр категории.
- **Настройки сканирования** — блок на экране карты: подсети (авто — с источником, ручные —
  добавить/удалить), исключения, интервал (только чтение, 6 ч).

## Безопасность и вежливость

- Никаких POST/PUT, логинов, перебора; только пути, перечисленные выше.
- Тела ответов в БД не хранятся (только выжимка: title, server, версия).
- Ошибки отдельных хостов не валят скан.

## Тесты

- Сканер работает через интерфейс `Dialer` (адрес→соединение), чтобы тесты отображали
  `(ip, port)` на локальные слушатели `127.0.0.1:<random>`; ARP-таблица — через интерфейс с
  фейковым содержимым `/proc/net/arp` (формат реального файла).
- Фикстура `internal/netscan/testdata/banners.json` (с живой сети, обезличена: IP 10.10.10.x,
  cookie/CSRF вырезаны): для каждого HTTP-ответа поднять httptest-сервер (TLS для https), отдающий
  записанные статус/заголовки/тело, и проверить распознавание: .1 MikroTik RouterOS, .10:8006
  Proxmox VE, .19:8007 Proxmox Backup Server, .12 Gitea, .17:81 Nginx Proxy Manager, .15:9091
  AdGuard Home (/control/status → 401), .15:80 — редирект nginx (за ним AdGuard: правило по
  Location), .25 Gotify, .33:3000 Semaphore UI, .13 qui, .16:3000 Docmost, .127:8080 Iris,
  .108 Apache default page, .23 nginx default page, .36 HPE iLO, .40:9001 S3 (RustFS/MinIO),
  .99 Synology (если по телу различимо; иначе nginx — зафиксировать в «Отклонениях»).
  SSH-баннеры: OpenSSH Debian 13, Ubuntu, dropbear, mpSSH → iLO, ROSSSH → MikroTik.
- OUI: BC:24:11 → Proxmox Server Solutions GmbH, 04:F4:1C → Routerboard.com, 9C:6B:00 → ASRock;
  locally administered → random.
- Подсети: из фикстуры `network-pve1.json` (1c) → 10.10.10.0/24; исключения; отказ на /16.
- Хранилище: alive=0 для пропавших, «забыть», ротация scans (50).
- Планировщик: интервал 6 ч, первый запуск через 5 мин, не параллельно, отмена.
- Фронтенд: построение графа из `GET /network` (роутер, узлы, гости, группы), фильтры, таблица
  сервисов — чистые функции в `lib/`, тесты на node:test.
- Никаких реальных сканов из тестов и при разработке.

## Критерий (проверяет ревьюер на живой сети)

Скан домашней /24 из LXC контроллера за ≤ 2 мин находит не меньше хостов, чем ручной аудит
(~49 адресов, кроме телефонов без открытых портов), узнаёт Proxmox ×3, PBS ×2, AdGuard,
MikroTik ×2, Gitea, NPM, iLO; гости связаны с инвентарём.

## Отклонения (по факту реализации)

- **Порты.** В списке из спеки ровно 134 уникальных порта (не «~150»); в `netscan.Ports` — те же 134, у каждого
  подсказка протокола проб (`http`/`https`/`ssh`/`banner`/`none`/`auto`).
- **Подсети мостов собирает инвентарь, а не скан.** Шаг «Узлы и хранилища» сбора 1e-1 теперь запрашивает
  `/nodes/{n}/network` и кладёт в снимок `subnets[{node, iface, cidr, gateway}]` (мосты `bridge`/`OVSBridge`
  с адресом IPv4); для SSH-сервера — `ip -4 -j addr` (best effort, без `lo`, link-local, docker/veth/br-/virbr).
  Скан берёт подсети из последних снимков, поэтому они не новее снимка. Шлюз моста (`gateway`) нужен карте как
  корень графа «роутер». Подсеть больше /22 из мостов не валит скан: она остаётся в списке с `error` и не
  сканируется; ручная подсеть больше /22 — 400. Дополнительно отказ для 127/8, link-local, multicast и 0.0.0.0
  (тестовый `Dialer` от этого не зависит). Ручных подсетей не больше 16; исключение — IP или подсеть любой ширины.
- **MAC гостей** берутся из `hwaddr` (LXC) и `hardware-address` (агент QEMU) тех же запросов, что дают IP, —
  без отдельных запросов `config`, поэтому у остановленных гостей MAC нет. В хост подставляется, только если
  у гостя ровно один MAC и ARP его не дал; ARP-MAC всегда главнее.
- **ARP только для «своих» подсетей:** `ARP.Local(prefix)` — у машины есть интерфейс в подсети. В чужих подсетях
  таблица содержит MAC роутера, поэтому ни MAC, ни «жив по ARP» оттуда не берутся.
- **Правила и фикстуры.** `.15:80` (nginx, 301 на `https://10.10.10.15/`) по ответу AdGuard не распознать: он
  «Веб-сервер nginx — перенаправляет на https://…»; AdGuard узнаётся на `:9091` (302 `/login.html` →
  `/control/status` = 401) и вообще на любом порту по `Location: /login.html` + ответу `/control/status`.
  `.99` — Synology по телу (скрытые `prefer_https`/`https` и `location.replace` на порты 5000/5001), порты в
  деталях. Добавлены правила сверх списка: TP-Link (тело ведёт на `/webpages/login.html`, это `.3` с dropbear),
  Sonarr/Radarr/Lidarr/Prowlarr по заголовку, Docker API, WireGuard/OpenVPN, Memcached, MongoDB, MSSQL, RDP, VNC.
  Iris отнесён к «media» (веб-клиент Mopidy), Gotify — к «monitoring», Docmost — к «other». `.30:443`
  (панель за nginx с редиректом на `/login`) — просто «Веб-сервер nginx»; `.38:3000` (400 «Host validation
  failed») — «HTTP, ответ 400»; `.34:443` (таймаут) — «Открытый порт 443, не ответил на запрос».
- **TLS без проверки цепочки.** Проба ходит `InsecureSkipVerify` (сертификаты домашних устройств самоподписанные,
  ничего секретного не отправляется); сам сертификат (CN, SAN, издатель, срок, самоподписанность) записывается.
  Порядок для портов `auto`: TLS → если в ответ пришёл plain HTTP, GET по http → иначе баннер 1,5 с → иначе GET.
- **Нет отдельного SSE `/network/events`.** Хосты сохраняются одной транзакцией на шаге «Сохранение»; экран
  следит за job (события задач) и пока идёт скан опрашивает `GET /network` раз в 3 с. Добавлено
  `DELETE /api/v1/network/scan` (остановить скан); `409` на повторный запуск отдаёт `job` идущего скана;
  в `GET /network` добавлены `scanning`, `job_id`, `interval_hours`, `extra_subnets` (ручные подсети) и
  `gateway` у подсети.
- **Связь с инвентарём считается при чтении**, а не только при сканировании: `GET /network` ищет гостя/узел по
  IP, затем по MAC в свежих снимках (сохранённое поле `link` используется, только пока нет ни одного снимка).
  Работающие гости и онлайн-узлы, которых нет среди хостов, показываются как `source: "inventory"`,
  `no_response: true` — только после первого скана; в БД они не пишутся.
- **Отмена и ошибки.** Отменённый скан не трогает `hosts` и закрывает запись `scans` с ошибкой «отменено»;
  скан без подсетей падает на шаге «Подсети» и записи в `scans` не оставляет. Интервал считается от конца
  предыдущего скана (в том числе ручного и неудачного); `netscan.interval_hours` читается из настроек
  (по умолчанию 6) и в UI только показывается.
- **Время скана не измерено на живой сети** (запрещено правилами этапа). Худший случай для /24 по расчёту
  ≈ 254·134·0,7 с / 256 ≈ 93 с, если все адреса молчат (на практике ответы RST быстрее); раннего отсева
  «мёртвых» адресов по ARP нет — если живой замер выйдет за 2 мин, это первое, что стоит добавить.
- **Интерфейс не открывался в окне/браузере** (GUI не запускался): проверены `svelte-check`, сборка и тесты
  чистых функций (`netmap.js`, `layout.js`, `services.js`). Фильтры карты по умолчанию: клиенты показаны,
  остановленные и молчащие скрыты. `npm audit` ругается на `picomatch` (транзитивно через vite/svelte-check,
  не из новых зависимостей).
- **Раскладка карты (правка после проверки на 47 хостах).** Хосты лежат в узлах-контейнерах (`type: 'group'`,
  дети с `parentId`, `extent: 'parent'`): на каждый узел Proxmox — «<узел> (Proxmox)» (карточка узла — шапка, под
  ней сетка гостей до 6 колонок), для остальных — «Сетевое оборудование», «Серверы и хранилища», «Компьютеры и
  телефоны», «Неизвестные» (сетка до 5 колонок, колонок = min(5, ceil(√n)), карточка 180×68). Рёбра идут только
  роутер → группа. dagre раскладывает лишь роутер и группы; число групп в ряду подбирается перебором так,
