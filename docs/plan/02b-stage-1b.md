# 02b. Этап 1b — подключение целей

Цель: из мастера подключить готовый Proxmox (узел или кластер) или отдельный Linux-сервер по SSH.
Hestia проверяет доступ, показывает отпечатки и план изменений, после подтверждения выполняет
план задачей (job) с откатом при ошибке и дальше работает только своим ключом/API-токеном.
Пароль пользователя нигде не сохраняется.

## Решения

- **Вся настройка Proxmox — по SSH через CLI** (`pveum`, `pvesh`), а не через API-тикет.
  Так один путь работает и с паролем, и с ключом. API Proxmox (:8006) дальше используется
  только с API-токеном Hestia.
- **TOFU (доверие при первом подключении)**: SHA256-отпечаток SSH host key и отпечаток
  TLS-сертификата API :8006 показываются пользователю в шаге проверки и сохраняются после
  подтверждения. Несовпадение позже → ошибка «отпечаток изменился», без подключения.
- **Секреты**: мастер-ключ `<data>/master.key` (32 случайных байта, 0600, создаётся при первом
  старте). Секреты в таблице `secrets` (AES-256-GCM, nonce на запись). Хранятся: приватный
  SSH-ключ Hestia, API-токен Proxmox. Не хранятся: пароли пользователя.
- **SSH-ключ Hestia**: один ed25519 на контроллер, генерируется при первом старте; публичная
  часть — `GET /api/v1/identity` (`{ssh_public_key, fingerprint}`), комментарий `hestia@<hostname>`.
- **Учётные данные проверки** (пароль/ключ из формы) живут только в памяти: «сессия проверки»
  с id и TTL 10 минут, удаляется после подключения или по истечении.

## Proxmox: проверка (без изменений)

SSH на `host:port` (по умолчанию 22, пользователь root) паролем или ключом. Команды:
- `pveversion` → версия; не Proxmox → понятная ошибка «это не Proxmox — подключите как отдельный сервер»;
- `cat /etc/pve/.members` (JSON) → имя кластера, узлы (имя, IP, online); нет файла → один узел;
- `pveum user list --output-format json`, `pveum role list --output-format json`,
  `pveum user token list hestia@pve --output-format json` (если пользователь есть) — чтобы
  план показал, что уже есть;
- TLS к `host:8006` → отпечаток сертификата.

Ответ проверки: `{probe_id, kind:"proxmox", host_key_fp, api_cert_fp, version, cluster, nodes[],
plan:[{id, title, detail}]}`.

## Proxmox: план (по умолчанию)

1. Роль `Hestia` с привилегиями: `Sys.Audit, Datastore.Audit, Datastore.AllocateSpace,
   Datastore.AllocateTemplate, VM.Audit, VM.Allocate, VM.Clone, VM.Config.Disk, VM.Config.CPU,
   VM.Config.Memory, VM.Config.Network, VM.Config.Options, VM.PowerMgmt, SDN.Use, Pool.Audit`
   (если роль есть — сверить и дополнить).
2. Пользователь `hestia@pve` (realm pve, без пароля), комментарий «Hestia controller».
3. ACL: `/` → `hestia@pve` → `Hestia`.
4. API-токен `hestia@pve!hestia` с `--privsep 0`, значение сохраняется в secrets.
   Токен с таким именем уже есть → удалить и создать заново (показать в плане).
5. Публичный SSH-ключ Hestia в `/root/.ssh/authorized_keys` (нужен для `pct exec` на этапе 1c).
   В кластере это симлинк на общий `/etc/pve/priv/authorized_keys` — добавить один раз,
   проверить с каждого online-узла подключением ключом Hestia. Если ключ уже есть — пропустить.
6. Проверка: API `GET /api2/json/version` и `/nodes` с токеном; SSH ключом Hestia на каждый узел.

Каждый пункт имеет откат (удалить токен, ACL, пользователя, роль если создана нами, строку
ключа). При ошибке job выполняет откаты созданного в обратном порядке и падает с понятной
ошибкой; созданное до этого не остаётся.

## Отдельный сервер

Проверка по SSH: `uname -srm`, `/etc/os-release`, `nproc`, `free -b`, `df -B1 -x tmpfs -x devtmpfs`,
`command -v docker`, `id -u`, `sudo -n true` (если не root) → факты и отпечаток host key.
План: добавить публичный ключ Hestia в `~/.ssh/authorized_keys` пользователя (создать каталог
0700/файл 0600 при необходимости), проверить вход ключом. Откат — удалить строку.
Предупреждение в ответе, если нет root и нет `sudo -n` (часть функций будет недоступна).

## Модель данных

`targets(id, kind proxmox|ssh, name, host, port, ssh_user, host_key_fp, api_cert_fp,
cluster, token_id, token_secret_ref, created_at)`, `target_nodes(target_id, name, ip, online)`,
`secrets(id, purpose, nonce, ciphertext, created_at)`.

## API (с входом)

- `GET  /api/v1/identity`
- `POST /api/v1/targets/probe {kind, host, port?, username?, auth:"password"|"key",
  password?, private_key?, passphrase?}` → ответ проверки (см. выше) | 400/422 с понятной
  ошибкой (не резолвится, отказ в доступе, таймаут 10 с, не Proxmox).
- `POST /api/v1/targets {probe_id, name?, accept:{host_key_fp, api_cert_fp?}}` → 202
  `{job}`; job выполняет план; при успехе цель появляется в списке. Отпечатки должны совпасть
  с отпечатками из проверки, иначе 409.
- `GET  /api/v1/targets` → `{targets:[...]}` (без секретов)
- `GET  /api/v1/targets/{id}` → цель + узлы
- `DELETE /api/v1/targets/{id}?revert=true|false` → 202 `{job}`; `revert=true` откатывает
  изменения на цели (токен, ACL, пользователь, роль, строка ключа) ключом Hestia, затем
  удаляет запись; `false` — только забыть локально.

## Интерфейс

- Мастер, «Готовый Proxmox» / «Отдельный сервер» → форма: адрес, порт (22), пользователь
  (root), способ входа (пароль | ключ: вставить текст), кнопка «Проверить».
- Экран результата проверки: что найдено (версия, кластер, узлы / ОС, CPU, RAM, диски),
  отпечатки (host key, TLS) с пояснением «сверьте, если сомневаетесь», список изменений плана,
  кнопка «Подключить» → прогресс задачи (как на экране задач) → готово.
- Экран «Системы» (простая версия): список подключённых целей, узлы, «Удалить» с выбором
  «откатить изменения на сервере» (по умолчанию да).
- Карточка «Чистый Debian → Proxmox» остаётся серой.

## Тесты

- In-process SSH-сервер (golang.org/x/crypto/ssh) с фейковым исполнителем команд:
  сценарии «Proxmox-кластер из 3 узлов», «одиночный узел», «не Proxmox», «отказ в доступе»,
  «ошибка на шаге токена → откат», «повторное подключение (роль/пользователь уже есть)»,
  «смена host key → ошибка».
- httptest TLS-сервер вместо API :8006 (версия, /nodes) с проверкой заголовка
  `Authorization: PVEAPIToken=hestia@pve!hestia=<secret>`.
- secrets: шифрование/расшифровка, неверный ключ → ошибка, файл 0600.
- Фронтенд: валидация формы, reducer результата проверки.
- Никаких обращений к реальной сети 10.10.10.0/24 из тестов и при разработке.
