# 00. Видение

## Что это

Hestia — «филиал своего интернета» в домашней сети, который настраивается без мучений.
Одно приложение: поставил на ПК → указал сервер(ы) → Hestia развернула себя на сервере →
нашла, что уже есть → предложила основу → дальше каталог сервисов с шаблонами.

## Сценарий пользователя (целевой)

1. Ставит приложение Hestia на Linux-ПК.
2. Мастер спрашивает, что у него есть:
   - готовый Proxmox (один или несколько узлов / кластер);
   - чистый Debian — Hestia поставит на него Proxmox;
   - отдельный сервер без Proxmox (просто Linux по SSH).
3. Вводит адрес и доступ (пароль или ключ). Hestia переводит доступ на свой ключ / API-токен.
4. Hestia ставит себя туда (LXC на Proxmox или systemd-сервис на отдельном сервере) и переносит
   туда своё состояние. Десктоп-приложение становится клиентом.
5. Hestia обследует сеть: узлы, ресурсы, гости, сервисы, карта сети.
6. Если основы нет — предлагает поставить начальные плагины (DNS, CA, proxy...).
   Если нашёлся AdGuard — предлагает прописать себя как `hestia.home` (домен можно выбрать)
   и дальше работать через веб.
7. Каталог: «поставить Samba сюда, 500 ГБ, шаблон “большие файлы”, [x] подключить к этому ПК»,
   «подключить существующий Iris», и т.д. При подключении существующего — аудит настроек и
   предложения исправить.

## Принципы

- **Без мучений по умолчанию.** Каждый шаг имеет разумное значение по умолчанию; эксперт может
  раскрыть детали.
- **Ничего не ломать молча.** Любое изменение существующей системы — только после показа плана
  и подтверждения. Обнаружение и аудит — только чтение.
- **Один бинарник.** Контроллер, веб-панель и (позже) агент — один Go-бинарник с режимами.
- **Один интерфейс.** Svelte-фронтенд одинаков в десктопе и в вебе.
- **Плагины декларативны.** Схема полей, пресеты, установка, adopt, аудит, интеграция с ПК.
- **Любой транспорт.** Proxmox API, SSH по ключу, SSH по паролю (только для первого входа).
- **Своё, где это ценность.** Уникальное у Hestia — связка «сервер ↔ клиентский ПК»
  (подключение шар, репозиториев, доверие к CA) и конвейер «сборка → репозитории → клиенты».
