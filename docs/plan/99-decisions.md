# 99. Решения и открытые вопросы

## Принято (2026-11-17)

- Проекты HomeLAN живут в общем каталоге проектов HomeLAN; основной — hestia/.
- Всё поставляется под именем Hestia (контроллер, панель, агент, плагины).
- Стек: Go + Svelte 5 + Tailwind 4 + DaisyUI 5 (как Rhea и Iris).
- Desktop-оболочка: **Wails v3**.
- Карта сети: **Svelte Flow** (@xyflow/svelte).
- Ресурсы LXC контроллера по умолчанию: 1 vCPU / 512 МБ / 4 ГБ (пересмотреть по факту).
- Лицензия: **MIT**.
- Первая платформа клиента — Linux (десктоп-приложение).
- Цели: готовый Proxmox, отдельный сервер по SSH. Вариант «чистый Debian → Proxmox»
  в MVP **виден в мастере, но неактивен** («скоро»); реализация — после MVP.
- Hestia ставит себя на цель и работает оттуда; есть веб-панель.
- Найден AdGuard → предложить rewrite `hestia.home` (домен выбирается); пока без сертификата.
- Пока плагинов нет — после обследования сразу обзор систем и карта сети.
- Старый hestia-backend и Godot-клиент не трогаем; используем как донор кода/UX.

- Go-модуль `hestia` (как `module iris`); репозиторий будет публичным.
- Wails v3.1.0; код Wails только под build tag `desktop`, серверная сборка — CGO_ENABLED=0
  (детали — 02a-stage-0.md).

- Самоустановка (2026-11-18, 02d): LXC на узле с наибольшей свободной RAM (pve1), VMID служебных
  гостей Hestia — с 900, IP по DHCP + ручная резервация на MikroTik (позже Hestia будет настраивать
  MikroTik сама), 1 vCPU / 512 МБ / 4 ГБ на local-lvm, непривилегированный CT с nesting=1 через
  API-токен; состояние переносится, ПК становится клиентом (`remote.json`), вход — handoff-токеном.

- Обновление (2026-11-18, 02e): два пути — из desktop-приложения (payload, офлайн) и с GitHub
  `uxerror/hestia` (раз в сутки, только уведомление, установка по кнопке). Версии — теги vX.Y.Z +
  git describe; dirty-сборки — с предупреждением; даунгрейд запрещён. Релизы подписываются ed25519
  локально (ключ у пользователя), `make release` выкладывает через gh. Применение — root-скрипт
  через `systemd-run` с бэкапом БД и автооткатом.
