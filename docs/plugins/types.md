# Реестр типов связей Hestia

Тип порта (`provides`/`requires` в манифесте) задаёт контракт данных, которые поставщик отдаёт
потребителю (`binding`), и — для портов с `"client": true` — что поставщик делает на устройстве.
Связь допустима только при **точном** совпадении типа. Протокол связей — [`protocol.md`](protocol.md),
раздел «Связи». В Go — пакет `github.com/uxerror/hestia/sdk/types` (структуры, `Validate`, `Lookup`).

## Правила

- Официальные типы перечислены ниже (имя без префикса плагина). Сторонний автор вводит свои типы
  с префиксом своего плагина: `<plugin-id>.<имя>` (например, `my-backup.target`). Неизвестный
  официальный тип или чужой префикс — пакет отклоняется. Первые части имён официальных типов
  (`http`, `ca`, `postgres`, `smb`, `fs`, `tls`) нельзя использовать как id плагина; id `hestia`
  занят встроенным компонентом контроллера.
- `binding` — JSON-объект ≤ 64 КБ. Для официального типа Hestia проверяет его по контракту **до**
  передачи потребителю: лишние поля, отсутствующие обязательные, неверный формат — связь не
  создаётся (`failed` с текстом ошибки). Binding собственных типов передаётся как есть (объект, без
  секретных полей).
- Поля вида `secret`: поставщик возвращает значение строкой; Hestia хранит его зашифрованным как
  секрет связи `link:<id связи>:<поле>` и отдаёт потребителю ссылку `{"secret": "link:<id>:<поле>"}`.
  Потребитель читает значение `secret.get {instance: <свой экземпляр>, name: "link:<id>:<поле>"}` —
  только пока связь активна. В Go — тип `types.Secret` (`Value` у поставщика, `Ref` у потребителя).
- Внутри версии контракта поля только добавляются (необязательными); несовместимое изменение —
  новый тип.

Виды полей: `string` — одна непустая строка; `host` — имя хоста или IP; `port` — 1…65535; `url` —
ссылка `http(s)://` без логина в адресе; `pem` — сертификат(ы) PEM; `path` — абсолютный путь без
`..`; `enum` — одно из значений; `secret` — см. выше; `csr` — `CERTIFICATE REQUEST` PEM (≤ 16 КБ);
`names` — массив DNS-имён (строчные LDH, без `*` и завершающей точки, ≤ 32, без повторов); `ips` —
массив IP-адресов в обычной записи (≤ 32, без повторов); `time` — время RFC 3339; `sha256` — 64
шестнадцатеричных знака (допускается запись `AA:BB:…`).

### Запрос (`request`) и продление

У типа может быть **запрос** — что потребитель отдаёт поставщику до выдачи binding (первый такой
тип — `tls.cert`). Потребитель такого типа обязан реализовать `link.prepare` и класть
**предпросмотр** запроса (без секретов и ключей, у `tls.cert` — имена без CSR) в свой план
`link.plan` (`plan.request`); иначе связь недоступна: «плагин не умеет запрашивать сертификаты».
Hestia проверяет запрос по контракту типа, предпросмотр входит в хеш подтверждённого плана, а
полный запрос из `link.prepare` должен совпасть с ним по именам. Запрос хранится у связи (CSR не
секрет); в API видны только имена. Запрос от поставщика игнорируется.

**Продляемый** тип (binding с `not_before`/`not_after`) Hestia продлевает сама: на 2/3 срока задача
`link-renew` — `link.prepare {reason: "renew"}` у потребителя → `link.refresh {request}` у поставщика →
проверки → `link.apply {action: "update"}` у потребителя. Другие имена при продлении не выдаются
(связь `degraded`, нужен план `reissue`); ошибка — прежний binding остаётся, повтор через 5 мин,
15 мин, 1 ч, дальше раз в час.

## Официальные типы (версия контракта 1)

### `http.service` — HTTP-сервис

Веб-сервис: адрес, по которому потребитель к нему обращается.

| Поле | Вид | Обязательное | Описание |
|---|---|---|---|
| `url` | url | да | полный адрес, например `http://10.10.10.21:8080/` |
| `host` | host | да | имя или IP |
| `port` | port | да | порт |
| `scheme` | enum `http`/`https` | да | совпадает со схемой `url` |

Клиентская сторона (`client`): имя сервиса в `/etc/hosts` устройства (пример — `hestia-hello`).

```json
{"url": "http://10.10.10.21:8080/", "host": "10.10.10.21", "port": 8080, "scheme": "http"}
```

### `ca.issuer` — удостоверяющий центр

Домашний CA: корневой сертификат и способ выпуска (поставщик — HestiaCA). Уточнено в 2a-3 до первого
использования (контракт 1): `issue` стал необязательным и получил значение `tls.cert`, добавлено
`sha256`.

| Поле | Вид | Обязательное | Описание |
|---|---|---|---|
| `ca_pem` | pem | да | корневой сертификат |
| `sha256` | sha256 | нет | отпечаток `ca_pem` |
| `acme_url` | url | нет | ACME-каталог, если CA его даёт |
| `issue` | enum `rpc`/`tls.cert` | нет | `tls.cert` — сертификаты выдаются связью типа `tls.cert` с этим же экземпляром |

Клиентская сторона: установка корня в системное хранилище доверия устройства (Debian/Ubuntu —
`/usr/local/share/ca-certificates/` + `update-ca-certificates`, Arch — `trust anchor`).

```json
{"ca_pem": "-----BEGIN CERTIFICATE-----…", "sha256": "3fa1…", "issue": "tls.cert"}
```

### `tls.cert` — сертификат TLS

Сертификат сервера по CSR потребителя: закрытый ключ рождается у потребителя и никуда не уходит.
Тип с **запросом** и **продляемый** (см. выше). Клиентской стороны нет.

`request` (потребитель → поставщик):

| Поле | Вид | Обязательное | Описание |
|---|---|---|---|
| `csr_pem` | csr | да (кроме предпросмотра) | `CERTIFICATE REQUEST` PEM: только ключ и доказательство владения, имена из CSR не используются |
| `dns` | names | нет | DNS-имена, ≤ 32 |
| `ips` | ips | нет | IP-адреса, ≤ 32 (`dns` и `ips` вместе — хотя бы одно) |

`binding` (поставщик → потребитель; секретных полей нет):

| Поле | Вид | Обязательное | Описание |
|---|---|---|---|
| `cert_pem` | pem | да | листовой сертификат |
| `chain_pem` | pem | нет | промежуточные (у HestiaCA пусто) |
| `ca_pem` | pem | да | корень |
| `ca_sha256` | sha256 | да | отпечаток корня |
| `dns`, `ips` | names / ips | да | что выдано |
| `serial` | string | да | серийный, hex |
| `not_before`, `not_after` | time | да | RFC 3339 UTC |

**Проверки Hestia сверх схемы** (до передачи потребителю; любая ошибка — связь `failed` или
продление не засчитано, потребитель binding не видит): лист разбирается и проверяется цепочкой до
`ca_pem` (`serverAuth`, сейчас); `ca_sha256` — отпечаток `ca_pem`; открытый ключ листа равен ключу из
CSR запроса; SAN листа **ровно** равны `dns`/`ips` запроса (email/URI — нет); поля binding описывают
этот лист; лист действует ещё ≥ 1 ч (если срок листа меньше суток — тестовый режим — достаточно, что
он не истёк); корень тот же, что у этой связи раньше или у `ca.issuer`/других `tls.cert`-связей этого
же поставщика (смена корня — только новой связью). В Go — `types.CheckTLSCert`.

```json
{"cert_pem": "-----BEGIN CERTIFICATE-----…", "ca_pem": "…", "ca_sha256": "3fa1…",
 "dns": ["hestia.home"], "ips": ["10.10.10.30"], "serial": "5c1f…",
 "not_before": "2026-11-19T10:00:00Z", "not_after": "2027-02-17T10:00:00Z"}
```

### `postgres.db` — база PostgreSQL

| Поле | Вид | Обязательное |
|---|---|---|
| `host` | host | да |
| `port` | port | да |
| `database` | string | да |
| `user` | string | да |
| `password` | secret | да |

Потребитель получает:

```json
{"host": "10.10.10.22", "port": 5432, "database": "iris", "user": "iris", "password": {"secret": "link:7:password"}}
```

### `smb.share` — сетевая папка SMB

| Поле | Вид | Обязательное | Описание |
|---|---|---|---|
| `host` | host | да | |
| `share` | string | да | имя шары |
| `user` | string | да | |
| `password` | secret | да | |
| `vers` | string | нет | версия протокола для `mount.cifs`, например `3.0` |

Клиентская сторона: монтирование шары на устройстве.

### `fs.media` — каталог с медиа

| Поле | Вид | Обязательное | Описание |
|---|---|---|---|
| `path` | path | да | каталог, видимый потребителю (источник — SMB или локальный диск) |
